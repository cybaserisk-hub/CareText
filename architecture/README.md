# CareText — Trusted Autopilot foundation

This is a **design and database/policy starter**, not a live SMS sending system.

## Product decisions
- Human-reviewed batches are the default during the first 90 days.
- Eligible paying subscribers may opt in separately for each recipient relationship.
- No message is sent automatically without valid recipient consent and a disclosure of AI-autogenerated delivery.
- Changing sensitive preferences or off-limits topics pauses autopilot until samples are reviewed again.
- Autopilot never replies to inbound messages, changes schedule, changes recipients, or exceeds monthly allocation.
- Subscribers can pause, disable, report an issue, or revert to manual approval at any time.
- On opt-out, stop immediately; retain only required consent/audit evidence according to retention policy.

## Implementation order
1. Integrate with authenticated users, sender/recipient relationship IDs and verified consent records.
2. Set up server-only activation endpoint with 90-day eligibility and explicit checkbox + policy version.
3. Record explicit subscriber opt-in and queue subscriber in-app/email mode-change confirmations. Existing recipient v3 consent covers both models; require additional recipient notice only if final compliance review requires it. Narrower prior consent requires re-consent.
4. Generate drafts from sender profile and Learn Me settings, enforce off-limits and repetition filters.
5. Run queue worker with DB transaction, locking, idempotency, plan quota and opt-out recheck just before SMS submission.
6. Add pause, manual-mode fallback, report-a-problem, activity history, and notification workflows.
7. Add integration tests for double sending, STOP during queueing, stale profiles, exhausted quotas and payment failures.

## Important technical notes
- Database constraints are defense-in-depth, not authorization. Add Supabase RLS policies only after actual auth and relationship schemas exist.
- Queue sender must recheck live consent and account subscription state immediately before sending.
- Do not store raw card or bank details; Polar manages payment credentials.
- Do not deploy this starter as a production backend or enable SMS sending without consent/compliance review.
- Annual subscriptions: charge once per year; monthly: once per month, using Polar's actual next billing timestamp.
